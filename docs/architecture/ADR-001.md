# ADR-001: Project Architecture

**Status:** Accepted  
**Date:** 2026-05-17  
**Deciders:** Architecture Team

## Context

ObstetraScroll is a proof-of-concept for generating evidence-based Instagram Reels for midwives and obstetricians. The project needs a modern, type-safe web stack that can serve video content with interactive quizzes while orchestrating external AI services for media generation.

## Decision

We adopt a **SvelteKit monolith** architecture:

- **Framework:** SvelteKit 2.x with Svelte 5 runes (`$state`, `$derived`, `$effect`)
- **Language:** TypeScript (strict mode) throughout
- **Rendering:** Server-side rendering (SSR) for initial load, client-side hydration for interactive feed
- **Adapter:** `@sveltejs/adapter-node` — Node.js server deployed via Docker
- **Package Manager:** `pnpm` with frozen lockfile
- **Build Tool:** Vite via `@sveltejs/vite-plugin-svelte`

### Project Structure

```
src/
  app.html          — HTML shell
  app.css           — Global styles (CSS custom properties)
  app.d.ts          — TypeScript ambient declarations
  lib/
    client/         — Browser-only components and logic
      ReelFeed.svelte    — Main feed orchestrator
      ReelCard.svelte    — Single reel display + quiz
      InfoOverlay.svelte — Slide-up info panel
      reelFeed.ts        — Virtualization logic
    server/         — Server-only modules
      aiservices.ts     — AIServices Python subprocess client
      enrichQuiz.ts     — Quiz question generator
      facts.ts          — 100 evidence-based obstetric facts
      feed.ts           — Feed item builder
      reelPlanner.ts    — Reel brief planner (Zod-validated)
    types.ts        — Shared TypeScript types
  routes/
    +page.svelte    — Main page
    +page.server.ts — Page load function
    +layout.svelte  — Root layout
    +error.svelte   — Error page
    api/
      facts/        — GET /api/facts
      feed/         — GET /api/feed
      reels/        — POST /api/reels (plan a reel)
    poc/            — POC reel viewer
```

### Key Design Decisions

1. **BFF (Backend-for-Frontend):** Server load functions in `+page.server.ts` hydrate `page.data` for the client. No separate API gateway.
2. **File-based routing:** SvelteKit conventions for routes, layouts, API endpoints.
3. **CSS custom properties:** Design tokens in `app.css`, component-scoped styles via `<style>` blocks.
4. **Virtual scrolling:** Feed virtualization in `reelFeed.ts` uses scroll-snap + IntersectionObserver. Only renders 2 items ahead/behind the active index.
5. **AI orchestration via subprocess:** `aiservices.ts` spawns `uv run` commands against a Python monorepo (`AIServices/`). No HTTP calls to AI providers — all models run locally via MLX.

## Consequences

- **Positive:** Single deployment artifact (Docker image). Full-stack TypeScript. Fast iteration with HMR. Simple ops.
- **Negative:** AI generation tied to macOS/MLX hardware (Apple Silicon). Cannot scale AI work horizontally without rethinking.
- **Trade-off:** We accept local-first AI generation for the POC phase. Future iterations may extract AI services into a separate service.
